用 GitHub Pages 承载可浏览总知识地图，用本地 Markdown 做备份与发布源；每次沉淀都更新节点、关系和复盘机制。

框架分层

总入口

首页、知识地图、图谱索引，负责全局导航。

知识节点

concept、framework、decision、playbook、case、memory 等。

发布层

公开版、脱敏版、GitHub Pages 静态页面。

复盘层

review_after、质量门禁、节点升级/拆分/归档。

操作流程

  1. 价值筛选：判断 S/A/B/C/Drop。
  2. 类型判断：归为 concept、framework、decision、playbook、case、memory、review、reference 或 inbox。
  3. 快速回顾：先让未来的自己 30 秒内重新理解。
  4. 框架定位：放入总知识树，并生成可交互图谱。
  5. 节点写作：生成完整 HTML/Markdown 与元数据。
  6. 发布判断：区分 public、private、needs-redaction、no。
  7. 索引更新：维护首页、知识地图和 graph.json。
  8. 复盘演化：设置 review_after，判断未来是否拆分、合并或升级。

质量门禁

  • 是否能快速重读？
  • 是否有上级分类和关联节点？
  • 是否能在 GitHub Pages 上独立阅读？
  • 是否标注边界、风险和隐私级别？
