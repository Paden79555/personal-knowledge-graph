广告算法成长作战图：Query 改写、CTR/CVR 与 Query 优选排序

这不是一页广告算法百科，而是一张“如何在当前业务里成长为核心工程师”的作战图。主线是：Query 改写候选生成 → 召回 → pCTR/pCVR 预估 → CPC/门控/排序公式 → Top1 Query → AB 实验 → Bad Case 回流。每个知识点都要落到数据口径、诊断指标、实现路径、线上风险和可交付项目。

核心判断：护城河不是“会模型”，而是能定义和诊断排序目标

AI 时代广告算法工程师的护城河，不是会不会调某个 CTR/CVR 模型，而是能否把业务目标拆成可学习、可诊断、可实验、可复盘的系统。对你来说，最值得打穿的闭环是：Query 改写候选生成 → CTR/CVR 预估 → CPC/门控/排序公式 → Top1 Query 选择 → 线上 AB → Bad Case 反哺。

① 执行层（易替代）

调包调参、跑 baseline、点 SFT/RL 平台、写规则、改公式参数、看单一 CTR 指标。AI 和平台化工具最先吃掉这层。

低护城河

② 工程层（部分替代）

打通数据、模型、排序、监控和 AB；把 LLM 离线能力蒸馏成线上可用模块；能解释 Top1 为什么胜出。

可迁移资产

③ 决策层（护城河）

定义优化目标，判断为什么不是只优化 CTR；权衡 CVR、RPM、相关性、广告主 ROI、用户体验和预算消耗。

核心团队能力
心法：不要追“最新技术”，要追“正好能解释当前业务问题、并能被线上实验验证”的技术。简历上“了解 LLM/CTR/CVR”不值钱；“围绕 Query 优选排序公式，定位长尾 query 的 pCVR 低估问题，通过 CVR 校准 + 长尾改写 + 门控策略调整，使某类 query 的 RPM/CVR 提升 X%”才值钱。

把当前资源武器化

真实流量 / 日志外面买不到的私域资产。按 query 头/腰/尾、改写类型、pCTR 桶、pCVR 桶、CPC 桶、门控状态拆，而不是只看整体 CTR。
AB 实验平台把技术假设变成实验：α 调整、CVR 系数、门控阈值、长尾改写、相关性约束、校准前后 Top1 变化。
傻瓜式 SFT/RL 工具不要只会点按钮。反拆样本来源、reward 定义、负样本构造、是否引入语义漂移，把平台工具变成理解训练链路的入口。
非技术 Leader用业务语言汇报：不是“ESMM 很先进”，而是“CVR 只在点击样本上学，会低估某些高转化 query，导致排序少赚且体验不稳”。
落后的 CNN CTR机会而不是纯劣势。你可以用 DeepFM/DIN/ESMM 做一次代际升级，形成“老模型 → 多目标排序体系”的代表作。
当前排序公式最好的学习入口。pCTR、pCVR、CPC、门控、Top1 每一项都能牵出一整套技术体系和实验体系。

1. Query 理解层
核心产物把自然语言 query 解析成结构化语义：品牌、品类、型号、属性、价格、场景、服务/购买/信息意图。
方法
词典分词、NER、实体链接、query-category 分类、LLM 意图解析。
指标
实体识别准确率、类目准确率、意图一致率、属性保留率。
常见坑
多义词消歧差；把“苹果维修”当“苹果手机”；把服务意图误判为购买意图。
2. Query 改写层
核心产物生成一组候选 query，而不是直接替换原 query。每个候选带来源、置信度、实体保留率、类目一致性、预估召回收益。
方法
规则/词典、query log、query-ad graph、向量相似、LLM 生成 + 约束过滤 + 蒸馏。
指标
改写触发率、坏改写率、无结果率下降、召回相关率、Top1 变化率。
3. 召回层
多路召回倒排召回负责精确匹配，向量召回负责语义覆盖，query2query 负责历史行为相似，query-ad graph 负责商业关联。
指标
召回量、有效召回率、相关广告占比、长尾覆盖率、召回 latency。
坑
召回多不等于好；向量召回容易语义近但商业意图错。
4. CTR/CVR 预估层
核心问题pCTR/pCVR 不只是模型输出，它们直接进入排序公式，因此数值可信度和分桶校准比单纯 AUC 更关键。
技术
DeepFM/DCN/DIN/DIEN/SIM、ESMM/MMoE/PLE、校准、debias。
监控
分桶校准、长尾桶、CPC桶、行业桶、改写类型桶。
5. 排序决策层
当前公式CPC门控通过：Score = pCTR × CPC^α × (1 + 10 × pCVR)；否则 Score = pCTR × CPC^α；按分降序取 Top1。
诊断
α sweep、CVR 系数 sweep、门控边界样本、Top1/Top2 分差、Top1 flip rate。
风险
高CPC低相关上浮、pCVR误差被放大、硬门控边界抖动、Top1强决策放大模型误差。

Query 改写深水区：12 类 Bad Case + 从简到难做法

Query 改写不是“把词换一下”，而是围绕候选 query 的生成、约束、召回、排序和回流建立闭环。每类 badcase 都要能落到分类、诊断、实现、进阶和指标。

QR-01
拼写/输入错误
错别字、拼音、英文缩写、型号空格、输入法混淆。
例子
“耐克跑些”→“耐克跑鞋”；“iphone15壳子”→“iphone 15 手机壳”。
分类
错别字、拼音近音、键盘近邻、型号格式、新词未收录。
简单做法
编辑距离、拼音相似、热门 query 词典、品牌/型号白名单。
进阶做法
Noisy Channel、BERT/seq2seq纠错、LLM候选生成 + 实体保护过滤。
指标
纠错准确率、无结果率下降、坏纠错率、纠错后CTR/CVR。
QR-02
实体丢失
品牌、型号、人群、地点等核心实体在改写后消失。
例子
“华为mate60手机壳”→“手机壳”；“耐克飞马40”→“跑鞋”。
简单做法
NER + 核心实体不可删除规则；品牌/型号词表保护。
进阶做法
entity-aware rewriting、实体链接、知识图谱约束、constrained decoding。
指标
实体保留率、品牌型号保留率、类目一致率、改写后CVR。
QR-03
属性丢失
颜色、价格、功能、场景等购买约束被改写抹掉。
例子
“红色连衣裙”→“连衣裙”；“防水蓝牙耳机”→“蓝牙耳机”。
做法
属性词表 + slot 抽取；解析为 {品类, 品牌, 属性, 场景, 价格意图}。
风险
CTR 不一定降，但购买意图变弱，CVR/RPM 可能下降。
QR-04
意图漂移
信息/购买/服务/比较意图被误改。
例子
“苹果手机维修”→“苹果手机”；“考研英语资料”→“英语培训”。
做法
query intent classifier、多任务意图识别、LLM意图解释、CTR/CVR联合校验。
指标
意图一致率、类目准确率、CVR变化、负反馈。
QR-05
类目错配 / 多义词坍缩
多义实体被落到错误行业或品类。
例子
“苹果”手机 vs 水果；“小米”手机 vs 食品。
做法
query-category层级分类、query-ad co-click类目约束、上下文/历史行为消歧。
指标
类目一致率、跨类目召回占比、人工相关性分档。
QR-06
过度泛化
改写变宽，召回变多，但意图被稀释。
例子
“儿童防滑运动鞋”→“鞋”。
做法
term importance；核心词不可删，弱修饰词可删；限制 drop term 数量。
判断
召回量上升但相关性/CVR下降就是过度泛化信号。
QR-07
过度具体化 / 幻觉
模型新增用户没表达的品牌、型号或属性。
例子
“跑鞋”→“耐克男士跑鞋”。
做法
禁止新增品牌/型号；LLM输出做实体差分；新增实体必须有上下文证据。
指标
新增实体率、幻觉实体率、坏改写率。
QR-08
欠改写
低召回/无结果 query 应该改写但没触发。
做法
无结果/低召回触发；改写必要性模型：召回数、稀疏度、历史表现、语义置信度。
指标
应改未改率、长尾覆盖率、no-result rate。
QR-09
过度改写
原 query 已足够好，却被改坏。
做法
原query保留为候选；改写置信度校准；bad rewrite classifier；回退策略。
指标
原query胜出率、改写后负收益率、Top1/Top2分差。
QR-10
长尾口语/地区/缩写表达
系统不理解低频但有商业意图的表达。
简单
同义词扩展、query expansion、类目模板。
进阶
LLM离线生成长尾同义表达、query2query graph、dense retrieval、蒸馏上线。
指标
长尾召回率、长尾CTR/CVR/RPM、长尾Top1变化率。
QR-11
高点击低转化
改写后更吸睛，但购买意图变弱。
诊断
CTR升但CVR/RPM降；高CTR低CVR样本池；意图错配人工复核。
做法
CTR × 相关性 × CVR × 商业价值联合rerank；引入CVR护栏。
QR-12
高CPC诱导
候选 query 因召回高CPC广告而上浮，但相关性差。
诊断
高CPC低相关Top1占比；CPC桶相关性和CVR。
做法
相关性门控、CPC截断/平滑、多目标排序、长期价值约束。
进阶路线：规则词典 → 统计共现/query log → 语义向量/双塔 → 生成式改写 → LLM离线生成 + 约束过滤 + rerank + 蒸馏/缓存上线。这最后一层最适合你当前“工具成熟但线上架构受限”的环境。

CTR/CVR：从模型名下钻到可信分数

CTR六层

特征层：用户/广告/query/上下文/交叉；模型层：LR/FM/DeepFM/DCN/DIN/DIEN/SIM；Bias层：position/popularity/selection；校准层：Platt/isotonic/分桶；长尾冷启层：平滑/语义/探索；评估层：AUC/GAUC/LogLoss/ECE/线上CTR。

CVR五层

标签口径：转化定义、窗口、归因、去重；SSB：点击空间训练、曝光空间预测；延迟反馈：假负样本；多任务：ESMM/MMoE/PLE；排序关系：pCVR进入公式后会放大校准误差。

CTR微观检查表

用户特征长期兴趣、短期意图、搜索/点击/购买序列、活跃度。检查事件时间、窗口、在线可得性，避免行为穿越。
广告特征广告主、行业、标题、落地页、历史CTR/CVR、CPC、预算状态。统计特征必须时间切分和贝叶斯平滑。
交叉特征query × ad、user × ad、query × category、user interest × query intent。先做可解释交叉，再上复杂模型。
序列建模DIN适合从老模型升一代；DIEN建兴趣演化；SIM/ETA处理长序列。工程上要考虑截断、缓存、latency。
校准pCTR进入商业公式，整体校准好不够，要看长尾query、高CPC桶、新广告桶、改写来源桶。

CVR微观检查表

标签口径转化是什么：下单/留资/激活/付费/咨询？窗口是1h/24h/7d？多次转化怎么记？归因给哪个query？
SSBCVR只在点击样本可观测，但线上要对曝光候选预测。ESMM用曝光全空间学习CTR和CTCVR，缓解样本选择偏差。
延迟反馈点击后很久才转化。先画点击到转化延迟CDF，再决定等待窗口、重标注、delayed feedback model。
多任务冲突CTR偏即时兴趣，CVR偏购买意愿。MMoE/PLE用共享与任务私有expert处理目标冲突。
长尾价值长尾query CTR低不等于没价值，可能购买意图强、CVR/RPM高。必须单独建桶评估。

排序公式：当前业务的最好学习入口

CPC门控通过：Score = pCTR × CPCα × (1 + 10 × pCVR)
CPC门控不通过：Score = pCTR × CPCα
按 Score 降序取 Top1 作为最优 query。公式不是终点，而是可诊断、可实验、可解释的目标函数原型。

pCTR

问题：是否校准？是否高估头部/低估长尾？是否受position/popularity bias污染？诊断：按query头腰尾、改写类型、CPC桶画校准曲线。

CPCα

α是商业价值权重。α越大，高CPC候选越容易上浮。做α sweep：0、0.25、0.5、0.75、1.0，观察Top1 flip和高CPC低相关占比。

1 + 10 × pCVR

10是人为放大系数。做系数 sweep：0、2、5、10、20。如果pCVR未校准，系数越大，错误越被放大。

CPC门控 + Top1

硬门控会有边界不连续；Top1会放大模型误差。看门控阈值附近样本、Top1/Top2分差、Top1来源分布和Top1 flip rate。

三张必须有的诊断表

Top1归因表每条候选query列出 pCTR、pCVR、CPC、门控、Score、来源、实体保留率、召回数、人工相关性，解释为什么Top1胜出。
Top1 Flip表比较不同α、CVR系数、门控开关下Top1变化，定位策略最敏感样本。
分桶收益表按query头/腰/尾、CPC桶、pCVR桶、改写类型桶看CTR/CVR/RPM/相关性，不让整体均值掩盖问题。

以点带面：长尾商业 Query 优化代表作

如果只选一个最有价值的代表项目，建议选“长尾商业 query 的 Query 优选优化”。它天然串起 Query 改写、召回、CTR、CVR、排序、门控、AB 和业务表达。

现象
长尾 query CTR 低、召回少，经常不成为 Top1，但人工看购买意图很强。
拆解
可能是长尾漏召、pCTR低估、pCVR样本少低估、CPC门控误杀、Top1被高CPC泛query抢走。
技术链
LLM离线改写补召回 → 相关性/实体过滤 → pCTR/pCVR分桶校准 → CVR/CTCVR识别购买意图 → 排序公式门控/权重调整。
实验链
目标桶：长尾商业query；主指标：CVR/RPM；护栏：CTR/相关性/负反馈/latency；诊断：Top1变化率、门控通过率、校准曲线。
简历表达
定位长尾query在召回、pCTR/pCVR估计和排序门控上的系统性低估，通过改写补召回、CVR校准、排序策略调整和AB实验完成闭环。

Bad Case归因模板

输入字段原query、候选query、Top1 query、pCTR、pCVR、CPC、门控、Score、来源、召回数、人工相关性、点击/转化。

输出动作补规则、改样本、加约束、校准模型、改门控、做AB、补监控、沉淀案例库。

实验、监控与质量门禁

模型监控

pCTR/pCVR分桶校准、漂移、长尾桶、高CPC桶、行业桶、改写来源桶。

改写监控

改写触发率、覆盖率、坏改写率、实体保留率、类目一致率、无结果率下降、召回数变化。

排序监控

门控通过率、Top1来源分布、Top1/Top2分差、Top1 flip rate、高CPC低相关占比。

AB实验模板

假设某类长尾query因为pCVR低估，导致高转化候选没有成为Top1。
样本长尾商业query，过去7/14/30天曝光超过X，点击少但转化意图强。
干预LLM改写补召回 + pCVR校准 + 门控策略调整 + 相关性约束。
主指标CVR、RPM、CTCVR、目标桶收益。
护栏指标CTR、相关性、负反馈、latency、fallback rate。
诊断指标Top1变化率、门控通过率、pCTR/pCVR分桶校准、长尾覆盖率、Top1/Top2分差。
判断标准整体不劣化，目标桶显著提升，护栏不下降，且badcase样本人工复核通过。
质量门禁：任何策略上线前必须能回答：影响哪些query桶？Top1变化了谁？pCTR/pCVR是否校准？CPC门控是否带来边界抖动？相关性和负反馈是否可控？

论文/业界方法地图：知道每个方向该往哪学

Query纠错/改写Noisy Channel Model、BM25/PRF、Learning to Rewrite、Session Reformulation、T5/BART/LLM Query Rewriting。重点学：从规则到生成式，再到约束和蒸馏。
语义召回/匹配DSSM、双塔召回、BERT matching、ColBERT、ANN向量检索、query-ad graph。重点学：语义相似不等于商业意图一致。
CTR模型LR+GBDT、FM/FFM、Wide&Deep、DeepFM、DCN/DCNv2、xDeepFM、DIN、DIEN、SIM/ETA。重点学：你从CNN升级的现实落点是DeepFM/DCN/DIN。
CVR/多任务ESMM、MMoE、PLE、Delayed Feedback Modeling、Entire Space Multi-task Model。重点学：CVR的样本选择偏差和延迟反馈。
Bias/校准Position Bias、PBM/Cascade Model、PAL、IPW、Doubly Robust、Platt Scaling、Isotonic Regression。重点学：广告分数进入排序公式，数值必须可信。
排序/多目标Learning to Rank、LambdaMART、Multi-objective Ranking、Counterfactual LTR、Thompson Sampling/UCB。重点学：CTR/CVR/RPM/体验不是单目标问题。

成长 Roadmap：恢复“人如何成长”的主线

阶段0：摸底与定切口

第1-2周
  • 画两张图：Query改写链路图、排序公式数据流图。
  • 捞300-500条badcase，按Query/召回/CTR/CVR/排序/口径六类归因。
  • 建立第一版Top1归因表：原query、候选query、Top1、pCTR、pCVR、CPC、门控、Score、来源、人工相关性、点击/转化。
交付物：《Query优选链路现状 + Bad Case分类报告》。

阶段1：打穿Query改写闭环

第1-3月
  • 选一个小切口：长尾有商业意图但漏召、品牌型号被改丢、高CTR低CVR意图漂移。
  • 用LLM/SFT平台生成候选，但评估必须看召回、相关性、pCTR、pCVR、Top1变化。
  • 建立实体保留、类目一致、置信度、相关性阈值过滤；通过缓存/蒸馏/规则兜底上线。
交付物：上线的Query改写优化模块 + “改写前后Top1变化与CTR/CVR/RPM影响”实验报告。

阶段2：CTR/CVR可信度建设

第4-6月
  • pCTR：分桶校准、position bias/popularity bias诊断、CNN→DeepFM/DIN升级可行性。
  • pCVR：明确标签口径，拉转化延迟分布，诊断点击空间/曝光空间差异，评估ESMM。
  • 排序侧：看校准前后Top1变化，尤其关注长尾低CTR高CVR/RPM样本。
交付物：《pCTR/pCVR校准与偏差诊断报告》+《CTR/CVR多任务建模升级方案》。

阶段3：排序策略与多目标优化

第7-9月
  • 做α、CVR系数、CPC门控阈值的离线重放和小流量AB。
  • 分析Top1 flip样本：哪些query因为高CPC/pCVR/门控成为Top1？是否符合业务直觉？
  • 补相关性约束和门控平滑，防止短期收入优化伤害长期转化和体验。
交付物：《Query优选排序公式诊断报告》+ 一个排序策略AB。

阶段4：端到端代表作

第9-12月
  • 建议主攻“长尾商业query优化”：从长尾漏召、pCTR/pCVR低估、CPC门控误杀到AB闭环。
  • 沉淀一套可复用方法：badcase归因 → 样本构造 → 模型/策略干预 → 监控 → AB → 复盘。
  • 形成能对外讲的项目故事：不是做了模型，而是改变了Query优选系统最终决策。
交付物：一个能写进简历/晋升材料的端到端项目。

阶段5：避开中间层陷阱

第12-24月
  • 70%砸硬技术：CTR/CVR多任务、Bias/Calibration、IR/Query Understanding、LLM可控生成与蒸馏、AB与因果。
  • 30%做业务差异化：广告主价值、用户体验、长尾商业价值、CPC/预算/转化链路、非技术表达。
  • 判断环境是否值得：能否拿日志、做AB、改策略、上线特征/小模型、让技术沉淀被认可。
退出红线：如果你只能改参数、拿不到日志/实验/模型诊断权限，这个环境不支持形成核心能力，应准备换组或换平台。
