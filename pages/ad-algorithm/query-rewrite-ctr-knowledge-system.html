广告算法知识体系：Query 改写 + CTR/CVR + Query 优选排序

这版把体系从“Query 改写 + CTR”扩展到完整的广告排序决策闭环：改写产生候选 query → CTR/CVR 预估用户响应 → CPC/门控/排序公式决定最终优选 query → AB 验证业务增量。重点不是罗列名词，而是把每个最下级节点拆到：问题定义、数据口径、模型技术、指标、失败模式、实验动作。

3 条主线Query 改写 · CTR/CVR · 排序策略
1 个排序公式pCTR × CPC^α × (1 + 10 × pCVR)
10 类 Bad Case现象 → 根因 → 技术树
细粒度叶节点定义 / 指标 / 坑 / 行动

核心判断：你真正要掌握的是“排序目标如何被构造”

Query 改写、CTR、CVR、CPC、门控、Top1选择不是分散模块，而是同一件事的不同切面：系统如何把“多个候选改写query”压缩成“一个最该展示/最该用来召回广告的query”。

CPC门控通过：Score = pCTR × CPCα × (1 + 10 × pCVR)
CPC门控不通过：Score = pCTR × CPCα
按 Score 降序取 Top1 作为最优 query。它隐含了三类偏好：点击概率、商业价值、转化价值；门控决定 CVR 是否进入排序。

把“当前公式”变成学习地图

pCTR点击倾向。牵出CTR特征、序列模型、位置偏差、校准、线上/离线一致性。关键问题：Top1 query 是因为真实更相关，还是因为 pCTR 偏高？
pCVR转化倾向。牵出CVR样本选择偏差、延迟反馈、ESMM/多任务学习、转化归因。关键问题：pCVR 是否只在点击样本上准？长尾是否低估？
CPCα商业价值权重。α控制“广告主出价”对排序的影响。关键问题：α增大是否牺牲相关性和长期转化？是否导致高CPC低质query上浮？
1 + 10 × pCVRCVR乘性增益。10是业务放大系数，不是数学真理。关键问题：10是否经过收益曲线、分桶实验、风险约束验证？
CPC门控决定CVR何时参与排序。关键问题：门控是否造成边界不连续？门控附近是否有排序抖动？是否误杀低CPC高转化query？
Top1强决策。只取Top1会放大模型误差和校准误差。关键问题：是否需要多候选融合、探索、兜底和置信度门控？

知识体系树：拆到“最下级节点该学什么、怎么用”

下面每个叶子节点都按“定义 / 口径 / 技术 / 坑 / 行动”拆细，避免停留在术语层。

A. Query 改写 / Query Understanding
A1. 改写类型分层
拼写纠错 Spelling Correction把噪声query还原为可召回query，适合错别字、拼音、输入法错误。
数据
query session中“错词→修正词”；低停留/无结果后用户二次输入；词典+拼音混淆。
技术
Noisy channel、编辑距离、BK-tree、混淆矩阵、seq2seq纠错。
指标
纠错触发率、坏纠错率、无结果率下降、召回广告相关性。
坑
品牌/型号被误纠；热词变化导致词典滞后；不能只用编辑距离。
行动
先捞无结果query Top N，人工分桶：错别字/新词/长尾实体/无商业意图。
同义/术语替换 Term Substitution把用户词映射到广告系统更容易理解的商业词。
数据
co-click query、同广告点击query、query-ad二部图、类目词库。
技术
PMI共现、embedding近邻、query2query图嵌入、term importance。
指标
替换后召回覆盖、相关性分档、CTR/CVR分桶变化。
坑
同义不等价；“便宜手机”替换成“手机”会丢失价格意图。
行动
为每个替换产出解释：保留了哪些实体、属性、意图，丢了什么。
查询扩展 / 收缩 Expansion & Specification扩展用于解决漏召，收缩用于解决过窄或噪声词。
数据
伪相关反馈文档、历史点击广告标题/类目、LLM生成候选。
技术
PRF、BM25 term reweighting、dense retrieval、LLM candidate generation。
指标
召回量、有效召回率、广告相关性、Top1最终分提升。
坑
召回多不代表好；扩展词会引入语义漂移。
行动
每次扩展同时记录新增召回广告中“高相关/低相关”的比例。
意图改写 Intent Rewriting不是改词，而是判断用户在买什么、查什么、比较什么。
数据
query类目、点击广告类目、购买/转化链路、人工意图标注。
技术
intent classifier、层级类目分类、多任务学习、LLM意图解析。
指标
意图一致率、类目准确率、CVR增益、投诉/负反馈。
坑
CTR高的意图未必是用户真实意图，容易clickbait化。
行动
对高CTR低CVR样本单独建“意图错配”bad case池。
生成式改写 Generative Rewriting用LLM/seq2seq产出候选改写，再用约束、打分、蒸馏上线。
数据
高质量query对、session reformulation、人工/LLM偏好标注。
技术
SFT、constrained decoding、reranker、teacher-student distillation。
指标
候选多样性、实体保留率、坏改写率、线上latency、AB增益。
坑
LLM会“看起来合理但商业不可用”；必须有实体/类目约束与回退。
行动
把LLM输出分三层：可直接用、需规则过滤、只适合做离线训练样本。
A2. 监督信号与样本构造
Session Reformulation用户自己连续改query，是最便宜的监督信号。
  • 正例：无结果/低满意后改成高点击query。
  • 负例：改写后快速返回或继续改写。
  • 难点：同session不一定同意图，需要时间间隔和点击/转化校验。
Query-Ad Click Graph通过共同点击广告建立query相似，但要防止热门广告造成伪相似。
  • 用去热门化PMI或归一化共现。
  • 分行业/类目建图，避免跨类目污染。
  • 可训练query embedding或query2query召回。
长尾样本增强长尾query没有足够点击，需要语义增强而不是硬等数据。
  • LLM生成候选 + 人工小样本校验。
  • 头部query模板迁移到长尾实体。
  • 蒸馏到小模型，线上只跑轻量模型/缓存。
B. CTR 预估
B1. 特征体系
用户侧特征用户画像、历史点击、搜索/浏览/购买序列、频控、活跃度。
关键
区分长期兴趣、短期意图、当前query意图；广告场景不能只看静态画像。
坑
行为穿越、窗口选择不当、训练/预测特征不一致。
行动
为每个行为特征标清：事件时间、回看窗口、是否在线可得、延迟。
广告/商品侧特征广告主、行业、标题、落地页、历史CTR/CVR、CPC、预算状态。
关键
后验统计必须平滑，长尾广告不能直接用裸CTR。
坑
用未来统计造成feature leakage；热门广告被过度放大。
行动
所有统计特征做时间切分与贝叶斯平滑。
交叉特征query × ad、user × ad、query × category、user interest × query intent。
技术
FM/DeepFM/DCN/xDeepFM、attention交互、cross network。
指标
整体AUC不够，必须看query桶/行业桶/长尾桶GAUC。
行动
从“query × 广告类目”开始做可解释交叉，别一上来盲目堆深模型。
B2. 行为序列建模
DIN对候选广告做target attention，从历史行为中挑相关行为。
  • 适合从CNN/浅层模型升一代。
  • 关注attention是否真的指向相关历史，不要只看AUC。
  • 线上代价：历史序列截断、embedding缓存、特征服务延迟。
DIEN建模兴趣演化，不只看历史行为集合，还看兴趣随时间变化。
  • 适合用户兴趣变化快的场景。
  • 难点是训练复杂、序列噪声大。
  • 先用DIN打底，再评估DIEN是否值得。
SIM / ETA长序列建模：先检索相关子序列，再精排attention。
  • 适合历史行为很长、短序列截断损失大的场景。
  • 关键是子序列检索召回质量。
  • 工程上要关注ANN/索引更新/在线延迟。
B3. 偏差与校准
Position Bias点击标签混合了真实兴趣和展示位置诱导。
  • 方法：position-as-feature、PAL、IPW、随机桶估propensity。
  • 诊断：同广告/同query在不同位置CTR差异。
  • 风险：位置特征预测时怎么置，需要和线上排序一致。
CalibrationpCTR不是只为排序，它进入商业公式，数值必须可信。
  • 方法：Platt scaling、isotonic、分桶校准、后验校准。
  • 指标：ECE、分桶预测/实际点击比、行业桶校准。
  • 风险：整体校准好，不代表长尾query/高CPC桶校准好。
C. CVR / 转化预估
C1. CVR定义与标签
CVR标签口径通常是点击后是否转化，但不同业务转化定义可能是下单、激活、表单、留资。
口径
必须定义转化窗口（1h/24h/7d）、归因方式、去重规则。
指标
CVR AUC、LogLoss、校准、CTCVR、GMV/RPM增益。
坑
窗口太短会把延迟转化当负样本；窗口太长训练反馈慢。
行动
拉一张“点击后转化延迟分布”，再决定训练窗口和延迟反馈策略。
CTCVR全空间点击且转化概率，常用关系：pCTCVR = pCTR × pCVR。
意义
CVR只在点击后可观测，但排序面对的是全曝光空间。
技术
ESMM联合建模CTR和CTCVR，隐式得到CVR。
坑
pCTR或pCVR任一校准错误都会传导到CTCVR。
行动
同时看pCTR、pCVR、pCTCVR三者分桶校准，不只看一个AUC。
C2. CVR核心问题
Sample Selection BiasCVR训练样本来自点击样本，但线上要对所有曝光候选估计转化倾向。
  • 典型方法：ESMM、全空间多任务、反事实/IPS校正。
  • 诊断：点击样本和曝光样本的特征分布差异。
  • 风险：只在点击空间验证CVR，会高估线上效果。
Delayed Feedback转化可能在点击后很久才发生，早期负样本可能是假负样本。
  • 方法：延迟反馈建模、样本等待窗口、正负样本重标注、survival思想。
  • 诊断：转化延迟分布、不同类目的延迟差异。
  • 行动：按行业/转化类型分别设窗口，不要一刀切。
Attribution / 转化归因用户可能多次点击、多query触达，最终转化归给谁会影响CVR训练。
  • 口径：last click、first click、multi-touch、时间衰减。
  • 风险：错误归因会把“助攻query”学成无效，把“收口query”过度放大。
  • 行动：至少产出query改写前后转化归因变化分析。
C3. CTR/CVR多任务
ESMM用曝光全空间同时学习CTR和CTCVR，缓解CVR样本选择偏差。
  • 适合：你已有CTR链路，希望把CVR体系补起来。
  • 关键：共享embedding + 两个任务头；pCVR由pCTCVR/pCTR隐式约束。
  • 风险：pCTR很小时CVR数值不稳定，需要裁剪/校准。
MMoE / PLE多目标共享与分化，解决CTR和CVR目标冲突。
  • CTR偏即时兴趣，CVR偏购买意愿，二者不总一致。
  • MMoE用多个expert和gate；PLE进一步区分共享/任务私有expert。
  • 评估必须看多目标Pareto，不是单指标最优。
D. Query优选排序策略
候选query生成原query、纠错query、同义替换query、扩展query、LLM生成query组成候选集。
  • 每个候选必须保留来源、置信度、实体保留率、召回覆盖。
  • 没有候选元信息，后续无法归因Top1为什么选错。
排序公式因子pCTR负责点击，CPC负责商业价值，pCVR负责转化价值，门控负责是否让CVR参与。
  • pCTR/pCVR必须同一候选query粒度下计算。
  • CPC可能是广告侧聚合值或候选召回集统计，口径必须固定。
  • α和10都是策略超参，要做敏感性分析。
Top1选择风险Top1会放大某个因子的误差，尤其是pCTR/pCVR未校准或CPC极端值。
  • 需要看Top1与Top2分差，小分差样本适合做探索或保守回退。
  • 需要监控Top1来源分布，避免LLM候选或高CPC候选异常占比。
E. 底层基础
IR / 检索倒排、BM25、ANN、dense retrieval、query-ad matching，是Query改写召回的地基。
因果与DebiasIPW、DR、uplift、position bias、selection bias，是CTR/CVR可信度的地基。
实验方法论AB、AA、CUPED、分层、互斥、sample ratio mismatch，是证明策略有效的地基。
工程系统特征一致性、延迟、缓存、回退、监控，是让模型活在线上的地基。

排序策略：把公式拆成可诊断、可实验、可迭代的系统

当前公式不是终点，而是一个可拆解的策略框架。你要能回答：每个因子从哪里来，数值是否可信，何时会错，错了怎么定位，怎么实验验证。

Score(q) = pCTR(q) × CPC(q)α × Gate(q)
Gate(q)=1 + 10 × pCVR(q) if CPC门控通过 else 1
q是候选改写query。最终选择 argmax_q Score(q)。

α 怎么理解

α是商业价值放大旋钮。α=0时CPC不影响；α越大，高CPC候选越容易上浮。它不是离线拍脑袋参数，应该通过收益-体验曲线选择。

敏感性分析CPC分桶

10 × pCVR 怎么理解

10是CVR放大系数，决定转化价值相对点击价值的权重。如果pCVR校准差，10会把误差放大。

校准风险CVR分桶

CPC门控怎么诊断

门控会带来边界效应：阈值附近两个query只差一点CPC，排序分可能突变。需要看门控通过率、边界样本、Top1切换率。

边界不连续Top1 flip

Top1怎么验证

Top1不是“排序完就完了”。要看Top1来源、Top1/Top2分差、Top1的pCTR/pCVR校准、Top1实际CTR/CVR/RPM。

可观测性归因报表

策略实验矩阵

α网格实验固定其他项，比较α ∈ {0, 0.25, 0.5, 0.75, 1.0} 对CTR、CVR、RPM、相关性、投诉/负反馈的影响。重点看高CPC桶是否劣化体验。
CVR系数实验比较系数 {0, 2, 5, 10, 20}。如果系数增大带来CTR下降但CVR/RPM上升，需要判断业务目标优先级。
门控阈值实验看门控通过率、阈值附近Top1切换率、低CPC高CVR被压制比例。必要时从硬门控改成平滑门控。
校准前后实验对pCTR/pCVR做分桶校准，比较排序Top1变化率和线上收益。很多策略问题本质是模型分数不准。
相关性约束实验在Score外加最低相关性阈值或惩罚项，防止高CPC/高pCTR但语义漂移的query胜出。

建议新增的诊断报表

Top1归因表

每条候选query列出pCTR、pCVR、CPC、门控、Score、来源、实体保留率、召回数，解释为什么Top1胜出。

分桶收益表

按query头/腰/尾、CPC桶、pCVR桶、改写类型桶分别看CTR/CVR/RPM。

Top1 Flip表

比较不同α/不同CVR系数/门控开关下Top1变化，找策略敏感样本。

Bad Case → 技术体系：从现象牵出整棵树

下面不是泛泛“归因”，而是把失败现象拆到可执行的技术动作。

QR-01
语义漂移 Semantic Drift
改写后实体、属性、意图偏离，导致高分但不相关。
子类
过度泛化、实体漂移、属性丢失、多义词坍缩、商业意图错配。
诊断
实体保留率、类目一致率、改写前后召回广告相关性分档、Top1候选来源。
技术
entity-aware rewriting、constrained decoding、相关性reranker、实体/属性硬约束。
行动
建50-100条漂移样本，标注“丢了哪个实体/属性/意图”，倒推约束规则。
QR-02
长尾漏召 Long-tail Recall Miss
低频query召回为空或召回低质广告。
子类
倒排无命中、分词错误、实体未入库、语义表达新、改写未触发。
诊断
no-result rate、召回数分布、长尾query占比、扩展后新增召回相关率。
技术
query expansion、dense retrieval、LLM离线扩写、query2query图召回、缓存。
行动
优先选“有商业意图但无结果”的长尾query，不要把无商业价值query也拉进优化目标。
QR-03
过度改写 Over-rewriting
本来准确的query被改坏。
根因
缺少“是否需要改写”的前置判断，改写置信度不校准。
技术
改写必要性分类器、置信度门控、原query保留策略、bad改写回退。
指标
改写率、坏改写率、原query胜出率、改写后Top1分差。
CTR-01
pCTR虚高
某候选query因为位置/历史热度/样本偏差得到过高pCTR，压过真实相关query。
根因
position bias、popularity bias、训练/预测分布不一致、校准差。
技术
PAL/IPW、分桶校准、去热门化统计、按query类型GAUC。
行动
做Top1 pCTR校准表：预测pCTR桶 vs 实际CTR，按头/腰/尾query拆开看。
CVR-01
pCVR低估长尾/新广告
长尾候选query实际购买意图强，但因转化样本少被低估。
根因
转化稀疏、冷启动、样本选择偏差、归因窗口不合理。
技术
ESMM、MMoE/PLE、贝叶斯平滑、LLM语义特征、行业先验。
指标
长尾pCVR校准、CTCVR、转化延迟分布、行业桶CVR。
行动
把“长尾query的CTR低但CVR/RPM可能高”的样本单独建桶，不要用整体CTR直接否定。
CVR-02
延迟反馈导致假负样本
训练时当作未转化，几小时/几天后才回流转化。
诊断
按行业/广告类型画点击到转化延迟CDF，找80/90/95分位。
技术
样本等待窗口、延迟反馈loss、正负重标注、survival modeling思想。
行动
不要统一窗口；高决策成本品类转化更慢，应单独建模。
RANK-01
高CPC低质query胜出
CPC^α过强或相关性约束弱，商业价值压过用户体验。
诊断
高CPC桶Top1占比、相关性差评率、CTR/CVR/RPM三指标是否背离。
技术
α敏感性实验、相关性门控、CPC截断/平滑、长期价值约束。
行动
先做离线Top1 flip分析，看α变化到底让哪些query上浮。
RANK-02
CPC门控边界抖动
门控附近分数不连续，Top1不稳定。
诊断
门控阈值附近样本Top1切换率、Score跃迁幅度。
技术
硬门控改平滑门控、阈值分桶、置信度缓冲区。
行动
抽门控上下5%样本，逐条看Top1是否符合业务直觉。
RANK-03
CVR系数放大错误
pCVR不准时，1+10×pCVR会把误差放大到排序结果。
诊断
pCVR分桶校准、Top1中高pCVR低实际转化样本、CVR系数Top1 flip。
技术
CVR校准、系数网格实验、分行业系数、CTCVR替代/融合。
行动
上线前先做CVR系数从0到20的离线排序重放。
RANK-04
长尾query CTR低但商业价值不低
如果只看CTR，长尾query会被压制；但它可能CVR高、CPC高、意图明确。
根因
长尾曝光少导致CTR估计不稳；头部query泛化强但购买意图弱。
技术
分桶校准、贝叶斯平滑、CVR/CTCVR联合、探索流量、语义先验。
行动
建立“长尾低CTR高CVR/RPM”专题报表，别让整体CTR掩盖它。

模型演进史：从CTR单点到多目标排序

线性与人工交叉

LR → LR+GBDT → FM/FFM

解决大规模稀疏特征和人工交叉。今天仍是理解广告特征工程的底层。

深度交叉

Wide&Deep → DeepFM/DCN/xDeepFM

把记忆与泛化、高阶交叉自动化。适合作为CNN老模型升级前的现代基线。

行为序列

DIN → DIEN → SIM/ETA

从“用户是谁”升级到“用户最近/长期对什么感兴趣”。这是CTR代际升级主战场。

CVR与多任务

ESMM → MMoE → PLE

解决CTR/CVR联动、样本选择偏差和多目标冲突。与你当前公式直接相关。

LLM与生成式

LLM语义特征 / 生成式改写 / 蒸馏上线

用于长尾、冷启动、语义理解，但必须落到延迟、缓存、可控性和AB增益。

现实升级路径：不要从CNN直接幻想LLM Ranker。更稳的是：CTR侧补DIN/DeepFM基线 → CVR侧补ESMM/延迟反馈 → 排序侧做公式可观测与参数实验 → Query侧做LLM离线改写与蒸馏。

分阶段成长 Roadmap：围绕当前公式做出代表作

阶段0：现状摸底与报表补齐

第1-2周
  • 画出候选query生成、pCTR/pCVR/CPC计算、门控、Top1选择的数据流。
  • 补Top1归因表：每个候选的pCTR、pCVR、CPC、门控、Score、来源、实体保留率。
  • 捞500条Top1错误样本，按QR/CTR/CVR/RANK四类归因。
交付物：《Query优选排序链路诊断报告》。

阶段1：先做排序公式的可解释诊断

第1个月
  • 离线重放不同α、CVR系数、门控阈值下Top1变化。
  • 建立头/腰/尾query、CPC桶、pCVR桶、改写类型桶的分桶收益表。
  • 找出“公式最敏感”的样本池，作为后续AB切口。
交付物：α/门控/CVR系数敏感性分析 + 一个小流量实验方案。

阶段2：补CTR/CVR可信度

第2-4个月
  • pCTR：做分桶校准、position bias诊断、DIN/DeepFM升级可行性。
  • pCVR：拉转化延迟分布、做SSB诊断、评估ESMM/多任务方案。
  • 把长尾query单独建桶，不再用整体CTR判断长尾价值。
交付物：pCTR/pCVR校准报告 + CVR样本偏差/延迟反馈方案。

阶段3：Query改写与排序联合优化

第4-8个月
  • 针对长尾漏召/语义漂移做LLM离线改写 + 约束过滤 + 蒸馏/缓存。
  • 新增相关性/实体保留约束，防止高CPC或高pCTR坏改写胜出。
  • 上AB：不只看CTR，还看CVR、RPM、相关性、长期负反馈。
交付物：一个“Query改写 × CTR/CVR排序”端到端代表作。

阶段4：从做策略到定义目标函数

第8-12个月
  • 沉淀一套多目标排序方法论：点击、转化、商业价值、体验、预算之间如何权衡。
  • 推动策略从固定公式走向可学习/可约束的多目标ranker或分层策略。
  • 对外能讲清：为什么这样定义目标，为什么不是只优化CTR。
交付物：组内Query优选排序框架文档 + 可复用实验模板。
退出红线：如果你只能改参数，无法拿到日志/实验/模型诊断权限，这个环境不支持你形成核心能力，应准备换组或换平台。

复盘 · 自检清单

公式理解

我能否解释Top1为什么胜出？能否拆出pCTR、pCVR、CPC、门控分别贡献了多少？

CVR理解

我是否知道CVR标签窗口、归因规则、延迟分布、点击空间/曝光空间差异？

长尾理解

我是否单独看过长尾query的CTR、CVR、RPM，而不是被整体指标平均掉？

校准理解

pCTR/pCVR进入排序公式前是否校准？哪些桶不准？不准会让哪些query胜出？

实验理解

我是否做过α、CVR系数、门控阈值的离线重放和线上小流量实验？

代表作

我是否能讲出一个端到端故事：发现bad case → 建诊断 → 改模型/策略 → AB提升？

一句话总结：你现在最值得切的不是“再学一个模型名”，而是围绕当前排序公式建立可解释、可诊断、可实验的体系。能把pCTR/pCVR/CPC/门控/Top1讲透并改出指标，才是从执行层跨到核心团队能力的关键。
