广告算法知识体系：Query 改写 + CTR

同一岗位里，越靠近“机器能独立闭环的执行”越易被替代；越靠近“定义问题 / 权衡取舍 / 承担结果”越是护城河。你的成长方向，就是沿着下面的箭头从左往右迁移。

① 执行层（易替代）

调包调参、跑 baseline、写常规特征、传统规则改写、标准 CNN/DeepFM 搭建、论文复现。

LLM 正在吞噬可迁移性低

② 工程层（部分替代）

离线 LLM 改写→蒸馏上线、序列建模落地、debias 方案实现、特征平台、AB 实验工程。

用 AI 放大稀缺中

③ 决策层（护城河）

问题定义、数据与指标设计、系统级权衡、因果与增量评估、承担业务 KPI。

AI 替不了越老越值钱
核心心法：不要追“最新技术”，要追“正好够用且能出指标”的技术。简历上“了解大模型”一文不值；“用 LLM 改写把某类 query 的 CTR 提升 X%”价值千金。让业务问题倒逼你去学正好够用的技术，而不是先囤技术再找场景。

把“手里资源”武器化

真实流量 / 日志这是外面买不到、LLM 也没见过的私域资产。用它做 bad case 考古，建“问题地图”。
AB 实验平台别等别人给实验。主动设计小流量实验，拿到“我提升了 X%”的硬故事。
傻瓜式 SFT/RL 工具把“点按钮”反向拆解：读它生成的配置、日志、底层调用，搞懂封装背后发生了什么——这是你在此环境补深度的唯一路径。
非技术 Leader双刃剑。坏处没人带；好处是你做技术决策的自由度极大，可主动定义方向。
落后的 CNN CTR做一次代际升级 = 组里“把模型升了一代的人”。在落后团队做代际改进，履历价值 > 先进团队做边际优化。

知识体系树（点击展开，逐层下钻）

这棵树就是“对标头部团队”的骨架。你不需要一次学完，但要知道每个 bad case 落在哪根枝上、往下还有多深。

A. Query 改写 / Query Understanding
A1. 改写类型分层
拼写纠错 Spelling CorrectionNoisy channel model、编辑距离、基于 query log 的纠错、键盘/拼音混淆矩阵
同义/术语替换 Term Substitution同义词典、共现统计、embedding 近邻、term importance / term weighting
查询扩展/收缩 Expansion/SpecificationPRF 伪相关反馈、query expansion、term dropping、分词与切分
意图改写 Intent Rewriting商业意图识别、query 分类、品类映射、意图保持约束
结构化改写 Structured实体识别 + 槽位、属性抽取、query 模板化
生成式改写 Generative (LLM)seq2seq、LLM 生成、constrained decoding、entity-aware rewriting
A2. 数据与监督信号
Session 内 reformulation 序列用户连续改写自己的 query，是天然的“改写监督”信号
Click graph / query-ad 二部图co-click、query2query 相似、图嵌入
长尾 query 数据稀疏LLM 离线生成改写 → 蒸馏；难负样本构造
A3. 评估体系
离线改写前后召回集质量、相关性分档标注、点击模型估计 gain（BLEU/编辑距离类很弱，慎用）
在线CTR/CVR/RPM、query coverage、无结果率 no-result rate、改写率、坏改写率
奖励设计陷阱纯 CTR 奖励会导致 clickbait 漂移 → 需 CTR × 相关性 × 商业价值的联合目标
A4. 工程与系统
延迟约束改写在召回前，对 latency 极敏感 → 离线改写 + 高频 query 缓存
大模型蒸馏小模型上线teacher→student，当下最稀缺的工程范式
与召回链路耦合改写后多路召回（倒排 + 向量 dense retrieval），兜底策略
B. CTR 预估 / Ranking
B1. 特征体系
特征类型用户画像、广告/item、上下文、交叉特征、行为序列、后验统计 CTR
核心难点高维稀疏、ID embedding、特征交叉、特征穿越 feature leakage 防范
B2. 行为序列建模（你升级的主战场）
DINtarget attention，按候选广告对历史行为加权
DIEN兴趣演化，GRU + attention 建模兴趣随时间变化
SIM / ETA长序列检索，从超长行为里检索相关子序列，解决长期兴趣
B3. Bias 体系（CTR 真正的深水区）
Position bias 位置偏差PAL、position-as-feature、IPW 逆倾向加权、双塔分离 propensity
Selection / Sample bias只观测到展示过的样本；CVR 的样本选择偏差 SSB → ESMM 全空间建模
Delayed feedback 延迟反馈转化延迟，CVR 建模核心难题，延迟反馈建模
Popularity bias / 长尾欠拟合热门过曝；长尾 item/user 稀疏 → 冷启动 + LLM 语义补充
B4. 校准 Calibration（广告特有，极重要）
为什么必须校准ecpm = bid × pCTR，pCTR 偏了直接影响计费与排序公平
方法Platt scaling、isotonic regression、后验校准、分桶校准
B5. 评估
AUC / GAUCGAUC 按用户分组，更贴近线上；AUC 提升 ≠ 线上提升
LogLoss / Calibration error广告里 calibration 与排序同等重要
B6. 冷启动 & 探索利用
新广告/新用户冷启动迁移学习、meta-learning、LLM 语义特征补充
E&E 探索利用Thompson sampling、UCB、contextual bandit —— CTR 与 RL 的交界
C. 广告系统全链路（建立全局观）
召回 → 粗排 → 精排 → 出价/机制 → 计费 → 预算 pacingquery 改写在召回前；CTR 在精排。把你的两个点放进整条链路，才有全局视角
竞价机制GSP / VCG、auction、reserve price，理解 pCTR 如何进入 ecpm 排序与计费
预算与平滑 Pacing预算控制、PID、流量分配
D. 底层基础（让上面所有枝叶站得住）
因果推断IPW、doubly robust、uplift / 增量建模 —— debias 和增量评估的根
信息检索 IR倒排索引、向量检索 ANN、相关性、BM25 → dense retrieval
实验方法论AB test、假设检验、方差缩减 CUPED、AA 实验、互斥分层
深度学习 & LLMattention/transformer、embedding、SFT、RLHF/RL、蒸馏、prompt 工程

Bad Case → 技术体系（以点带面的核心）

这才是“归因”的深度版本：每一个线上失败现象，都不是孤立的词，而是一条从现象 → 子类拆解 → 根因 → 该上的技术 → 该补的知识的完整链路。这张表，就是你和 Leader、上下游对话的硬资本。

QR-01
语义漂移 Semantic Drift
改写后意图偏离原始 query —— 远不止“词变了”这么简单
子类拆解
① 过度泛化（“红色耐克跑鞋”→“鞋”）② 实体漂移（品牌/型号丢失）③ 多义词坍缩（“苹果”手机→水果）④ 商业意图错配
根因
改写模型缺少 意图保持约束 与 实体感知；奖励信号只看召回量不看相关性
该上的技术
entity-aware rewriting、constrained decoding、term importance 建模、CTR×相关性联合奖励、LLM 改写 + 规则兜底
该补的知识
序列生成约束解码、NER/实体链接、query 意图分类、奖励建模（避免 clickbait）
QR-02
长尾漏召 Long-tail Recall Miss
低频 query 在索引里召回为空或召回劣质广告
子类拆解
① 倒排召回为空（无 term 命中）② 召回到但相关性差 ③ 改写未触发（欠改写）
根因
长尾 query 数据稀疏，传统 term 匹配覆盖不到；缺向量召回与语义改写
该上的技术
query expansion、dense retrieval 向量召回、query2query 相似、知识图谱补全、LLM 离线改写长尾 query → 蒸馏上线
该补的知识
ANN 向量检索、双塔召回、长尾建模、蒸馏、缓存策略
QR-03
过度改写 Over-rewriting
本来精确的 query 被改坏，引入噪声
根因
缺少“是否需要改写”的前置判断；改写置信度未阈值化
该上的技术
改写必要性分类器、置信度门控、改写率监控、bad 改写在线兜底回退
该补的知识
置信度校准、级联决策、在线 fallback 工程
CTR-01
Position Bias 位置偏差
高位置天然高点击，污染训练标签
根因
训练标签里的点击 = 真实兴趣 + 位置诱导，模型把位置当成了“好”
该上的技术
PAL、position-as-feature（训练带位置、预测置零）、IPW 逆倾向加权、双塔分离 propensity
该补的知识
因果推断 IPW / doubly robust、点击模型（PBM/cascade）、debias 评估
CTR-02
长尾欠拟合 + 新广告冷启
长尾 item/user 数据稀疏，pCTR 不准
子类拆解
① 新广告无历史 ② 长尾用户行为少 ③ pCTR 系统性偏差 → 影响 ecpm 计费
该上的技术
迁移/meta-learning、LLM 语义特征补充、E&E 探索（Thompson/UCB/contextual bandit）、冷启动校准
该补的知识
bandit / 探索利用、meta-learning、calibration、这是 CTR 与 RL 的交界
CTR-03
CVR 延迟反馈 + 样本选择偏差
转化延迟 + CVR 只在点击空间训练却要全空间预测
根因
转化回流慢导致负样本“假阴”；CVR 在“点击样本”上训练，存在 SSB
该上的技术
延迟反馈建模、ESMM（全空间多任务，CTR×CVR=CTCVR）、MMoE/PLE 多任务
该补的知识
多任务学习、样本选择偏差、延迟反馈 loss、转化归因

CTR 模型演进史（知道自己站在哪一代）

你们停在 CNN —— 看清整条线，你才知道“升一代”具体是升到哪、为什么。

2007-2014 · 线性时代

LR → LR + GBDT

大规模逻辑回归 + 人工特征交叉；Facebook 的 GBDT 自动特征。瓶颈：特征交叉靠人工。

2015-2017 · 自动交叉

FM / FFM → Wide&Deep

FM 自动二阶交叉解决稀疏；Wide&Deep 兼顾记忆与泛化。

2017-2018 · 深度交叉

DeepFM / DCN / xDeepFM

高阶特征交叉自动化。很多团队的“现代基线”就在这里。

2018-2020 · 行为序列

DIN → DIEN → SIM/ETA

target attention 建模用户兴趣；长序列检索建模长期兴趣。这是你最现实的“升一代”落点——从 CNN 跨到 attention 序列建模。

2019-至今 · 多任务 & 多目标

ESMM / MMoE / PLE

CTR+CVR 联合、全空间建模解决 SSB，多目标共享与分化。

2023-至今 · 生成式 & LLM

LLM 语义特征 / 生成式推荐

LLM 做语义特征、冷启动、长尾补充；generative retrieval / LLM-as-ranker 探索中。红利期，但要落到工程（蒸馏、延迟）才有价值。

升级策略：不要一步跳到最新。先做一个稳的代际改进（CNN → DIN 行为序列建模），拿到指标，再叠加 LLM 语义特征做长尾/冷启。一个上线见效的代际升级 > 十个跑不动的 SOTA 复现。

分阶段成长 Roadmap（贴合：初级 · 大厂 · 落后团队 · 非技术 Leader）

主线 12 个月 + 24 个月展望。每阶段都有可量化交付物，阶段 2 设“退出红线”。

阶段 0 · 摸底与定切口

第 1–2 周
  • 把能接触的 query 改写链路、CTR 模型现状画成两张图（数据流 + 模型结构）
  • 捞 200–500 条线上 bad case，按本页“失败地图”的子类做初步归因
  • 找一次傻瓜式 SFT/RL 任务，把它生成的配置/日志完整读一遍，列出“看不懂的 3 个点”逐个查清
交付物：《现状 + Bad Case 分类》文档 + “那个小到能独立掌控、又能出指标”的切口。

阶段 1 · 打穿第一个端到端闭环（Query 改写优先）

第 1–3 月
  • 选一类高频但改写差的 query（用阶段 0 的地图定位）
  • 用平台 LLM 做离线改写生成（这步可用傻瓜工具）
  • 深度补强：把离线大模型蒸馏成可上线小模型 / 高频 query 缓存——掌握“离线 LLM → 上线小模型”这条最稀缺的链路
  • 上 AB，拿指标
交付物：一个上线的改写模块 + 一份“相关性/CTR 提升 X%”的实验报告（人生第一个可对外讲的端到端项目）。

阶段 2 · CTR 代际升级 + 验证环境

第 4–6 月
  • CTR 从 CNN 推进一步：引入行为序列建模（DIN/SIM）或加 LLM 语义特征做冷启/长尾
  • 重点啃 样本 debias：position bias、delayed feedback、负样本构造——CTR 决定上限的脏活
  • 同步验证“环境到底托不托得住”：推动改进时，阻力是技术的还是组织的？
交付物：CTR 一次有指标的升级 + 一份 debias 方案。
退出红线：若 6 个月后发现阻力是你完全撼动不了的组织/存量问题、且没攒下可迁移资产 → 开始准备换组/换厂，别给自己留两年。

阶段 3 · 从“做模型”升级到“定义问题”

第 7–12 月
  • 主动承接一个“需懂业务才能定义、又需 AI 才能实现”的项目（策略背景在这里变优势）
  • 把阶段 1–2 沉淀成方法论：技术分享 + 内部文档，让“query 改写/CTR 找你”成为组内共识
  • 横向了解上下游（召回→粗排→精排→出价→计费），只补到能定义问题的程度，不贪全
交付物：1–2 个可量化项目 + 成为某垂直点的 go-to person。

阶段 4 · 明确选边，避开“中间层陷阱”

第 12–24 月
  • 警惕：纯“广度 + 架构整合”恰是 AI 时代风险最高的中间层（拼模块的活正被 Agent 侵蚀）
  • 抗 AI 的是两端：极致技术深度 或 承担商业结果的决策权
  • 给初级的配比建议：70% 砸可迁移硬技术深度，30% 做业务结合差异化——深度是地基
交付物：一个清晰的“深度 / 决策”选边，以及支撑它的代表作。

复盘 · 自检清单

每月对照一次。这些问题答不上来，说明你还停在执行层。

价值自检

本月我做的事，能不能用一句“把 X 指标提升了 Y%”讲清楚？讲给非技术 Leader 听，他听得懂吗？

深度自检

我用的 SFT/蒸馏/序列模型，离开这个平台我还能从头讲清原理和坑吗？还是只会点按钮？

问题定义自检

这个月我是“接需求执行”，还是有至少一次“我主动定义了该做什么、为什么做、值多少钱”？

环境自检

我推动改进遇到的阻力，是技术的（可学）还是组织的（撼不动）？退出红线触发了吗？

资产自检

我有没有在攒“带得走”的东西：可量化项目、bad case 地图、实验沉淀、领域 know-how？

迁移自检

我的工作重心，这个月有没有往“定义问题 + 系统权衡 + 承担结果”挪一点点？

一句话总结：你的方向（query 改写）正被 LLM 重构——与其被动观望，不如成为“把 LLM 能力工程化落地到广告链路”的那个人；同时刻意把重心从“执行模型”迁向“定义问题”。AI 越强，你越要站在它的上游：用它，而不是和它比执行速度。
